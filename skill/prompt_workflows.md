# 提示词工程流

本文档提供一项贯穿全程的归档与接续技能，以及六项工程技能，共七项提示词工作流。**已验证效果来自[协作记录](../report/llm_collaboration.md)中的具体案例；这些模板是在归档时统一整理的形式，未将“模板编写完成”冒充跨板卡或干净环境复用验收。** 每项均给出适用范围、输入、使用方法、输出、通过标准、效果来源及失效条件。先用 Skill 00 管理上下文，再按问题选择相应工程技能。

## Skill 00 集中归档与接口快照

**适用场景：** 多轮大模型协作、工程任务接续、换模型或换接手者，以及需要展示提示词与纠错过程的项目。尤其适合接口和软硬件状态持续变化、仅靠聊天记录难以可靠接续的任务。

**输入：** 现有总纲领、相关历史记录、当前工程入口、可验证接口以及本轮目标。没有的信息标注为“未核验”并说明影响，不用历史值猜填。

**形成依据：** 项目已有全部提示词集中存放的实践。P07 等文件将任务和执行报告保存在同一文件，P06 保留尝试与撤回，P22 在原记录中追加后续反馈；也存在早期提示词和报告分为两个文件的情况。本技能将这些经验统一成后续规范，不声称历史 93 份材料已经全部采用同一格式。

**目录与命名：**

```text
project_root/
├── skill/
│   └── README.md                         技能包导航及分类文档入口
├── prompts/                              提示词及执行报告的唯一集中目录
│   ├── README.md                         任务索引
│   ├── project_brief.md                  总纲领
│   ├── YYYYMMDD_HHMMSS_short-topic.md     同文件记录一项任务
│   └── YYYYMMDD_HHMMSS_next-topic.md      下一项任务引用前置记录
└── data/
    └── validation/                       原始验证数据及清单
```

这是供新项目使用的目录示例；本工作区继续以现有 `提示词/` 和 `总纲领.md` 为历史依据，没有为套用示例重命名原件。集中存放的是提示词和报告正文；大体积 IQ、抓包、构建产物与图片保存在对应证据目录，用路径和必要校验值关联。

- 文件名依次为完整日期、具体时间、简短任务描述；时间各字段补零，使用创建时间和 24 小时制，正文声明时区。对外工程包的描述用小写英文、数字与连字符，中文任务名称写在正文标题中。
- 同一任务的执行报告续写原文件，不另建一个容易失联的“最终报告”。确需保留已有分文件历史时，在新任务中列出其对应关系，不覆盖旧原文。
- 文件名保持稳定；同一秒存在不同任务时，为主题增加可区分后缀，不覆盖已有文件。
- 一轮中新出现的需求或事实带时间追加。仅“当前状态摘要”可以更新，原始提示词、执行事实和旧结论保留；旧结论被修订时明确指向新证据。

**可直接交给模型的提示词：**

```text
请按本项目的集中归档工作流执行当前任务。
1. 使用唯一提示词目录，一项任务一个日期_时间_简短主题.md文件。
2. 先读总纲领，再读本任务明确引用的相关记录，按需回溯，不全文重扫历史。
3. 执行前在当前文件记录目标、边界、历史依据、当前接口及通过条件。
4. 接口写明提供方、调用方、入口、输入输出、配置依赖、失败行为和核验依据。
5. 原始提示词保留；将模型分析、实际修改、验证结果和纠错续写同一文件。
6. 没有核验的接口标为未核验；未执行的步骤不写成已经通过。
7. 结束时列出执行前后接口差异、最终状态、恢复结果和下一步。
8. 更新集中目录索引；只有形成长期架构或接口决策时才同步总纲领。
9. 记录只使用技术角色与匿名样本，不加入单位、人员和敏感访问资料。
```

**当前接口快照至少回答的内容：**

| 维度 | 应写清的问题 | 不应替代它的表述 |
| --- | --- | --- |
| 执行位置与调用关系 | 谁提供、谁调用、功能实际在哪台设备运行 | “系统接口已接通” |
| 入口与调用方法 | 相对代码路径、函数或 HTTP 方法及路径、CLI 入口、主机别名 | 一个没有方法和部署位置的 URL |
| 输入与约束 | 必要字段、类型、单位、范围、目标或会话绑定及前置条件 | 只有参数名字，没有含义 |
| 输出与时效 | 必要字段、单位、空值语义、数据年龄或失效条件 | “返回正常数据” |
| 副作用与异常 | 是否切频、重启、写配置；失败、超时、拒绝及恢复行为 | 将读取状态和下发任务视为同一动作 |
| 核验与适用性 | 核验时间、源码或部署版本、实际结果、相关证据 | 只写文档的更新时间 |

**使用步骤：** 复制[同文件模板](case_templates.md#1-同文件任务与执行报告模板)创建文件；按[启动提示词](case_templates.md#2-开始一轮工作的提示词)执行；按[收尾提示词](case_templates.md#3-结束与交接的提示词)收尾；以[任务索引模板](case_templates.md#4-集中目录索引模板)格式更新目录索引。对纯文案任务等无外部接口的情况，写“本轮无接口变更”即可，不强行增加无关硬件字段。

**输出与通过标准：** 接手者应能从一个任务文件找到原要求、实际产出、纠错与最终状态；能沿链接定位前置任务及原始证据；能判断接口在什么条件下有效，而无需猜测旧参数。接口已改变时，执行前后快照必须显示差异；未改变也应说明核对范围。

**已验证效果与边界：** 协作记录中的 15 个案例及 93 份历史材料说明集中记录能够支持实际回溯：从任务追到执行结果、从报告找到接口和样本、从新事实找到旧结论修订。统一模板是基于这些实践的本次提炼，未另做陌生团队独立上手时间或跨项目效率测量。

**失效条件与处理：** 索引未更新、接口未核验、同一任务被复制成多份主记录、证据链接失效，都会削弱接续可靠性。遇到这些情况先明确有效记录并补核对；不要只按最新文件名选取配置。需要复用原始身份或网络样本时，另行使用匿名副本，技能模板中不嵌入真实身份和访问凭据。

## Skill 01 多来源工程事实核对

**来源：** [案例 4.1](../report/llm_collaboration.md#41-从多来源资料建立工程事实的优先级)、[案例 4.2](../report/llm_collaboration.md#42-从工具失败中修正工程操作方法)。适用于自定义 FPGA 板卡与上游参考工程整合。输入包括实际主工程、原理图、固定上游版本、当前软硬件资源及任务范围。

```text
请先建立工程事实，不直接改代码。
1. 确认实际打开和综合使用的主工程、BD、顶层、XDC及IP来源。
2. 按物理板卡、实际BD/XSA、对应上游协议、算法输入需求区分权威来源。
3. 列出冲突项、决定参数的依据、尚缺证据和允许修改的最小范围。
4. 对照位宽、IQ顺序、采样率、复位、CDC、DMA、地址和中断。
5. 交付来源对照及下一步检查；未运行的综合、实现和实机不写为通过。
```

**预期输出：** 有效输入清单、冲突表、模块与接口对应、未验证项、最小后续任务。通过标准是每个关键配置能追到来源，且不存在用外部参考覆盖板级事实的修改。

**已验证效果：** 为后续 OpenWiFi、双 RX 和 Linux 资源整合建立了明确边界，暴露了旧输出与源配置不一致等问题。

**失效条件：** 原理图版本或实际活动硬件不明、主工程选错、上游版本未固定。此时只能做差异整理，不能据此确认硬件连接正确。换题目可复用来源优先级，具体地址和引脚必须重查。

## Skill 02 时序与 CDC 定点排查

**来源：** [案例 4.4](../report/llm_collaboration.md#44-根据真实-cdc-协议修正时序分析)。适用于 routed 设计存在负 Slack，或时序例外与 CDC 结构需要共同检查的任务。

**输入：** 对应版本的布局布线结果、时序与 CDC 报告、相关 RTL/XDC、实际时钟关系，以及本轮允许的构建次数和修改范围。

```text
请基于当前布局布线结果排查时序，只处理最有依据的一类问题。
1. 提取最差路径的起终点、时钟、Slack、逻辑级数及逻辑和布线延迟。
2. 区分组合逻辑、时钟关系、跨域协议和约束覆盖问题。
3. 若涉及多位CDC，先说明数据更新机制、稳定窗口和接收协议。
4. 禁止以放宽时钟、无依据false path或猜测multicycle换取正WNS。
5. 定点修改后执行本轮约定的综合与实现，比较时序和例外覆盖。
6. 报告剩余CDC、外部I/O约束及板级签核缺口。
```

**预期输出：** 路径证据、协议解释、修改理由、前后时序和剩余问题。通过标准包括约束对象准确、修改有协议依据、实现报告真实完成，而不仅是 WNS 变正。

**已验证效果：** 本项目限定 TX IQ 路径修复后 WNS 从 -0.684 ns 到 +0.559 ns，建立违例端点从 32 到 0。

**失效条件：** 未布局布线、数据稳定协议无法证明、存在真正无保护的多位跨域。不能把本例 `-datapath_only` 写法照搬为通用 CDC 修复。

## Skill 03 双通道 IQ 来源与新鲜度核验

**来源：** [案例 4.6](../report/llm_collaboration.md#46-操作者新事实使换线实验的因果结论失效) 至 4.9。适用于有帧元数据和硬件时间标识的同步接收或测向任务。

**输入：** 原始双通道 IQ、独立完整帧记录、采集和 RF 配置、阶段时间界限、目标来源及操作者确认的物理状态。缺少其中某类证据时，先限定能验证到哪一层。

```text
请先证明IQ属于本阶段、本目标和可关联的空口帧，再计算角度。
1. 记录站点、采集会话、频率、双路增益、采样率和当前物理操作状态。
2. 阶段切换执行可读回的清空，保存阶段时间界限和丢弃窗口。
3. 保存原始IQ与完整参考帧，独立验证FCS、内容哈希及硬件时序关联。
4. 检查重复IQ、倒退时间、旧内容换新时戳、错误来源和错误时序反例。
5. 区分站内同源核验和跨站同次发射；重复空帧不得仅凭哈希参与交汇。
6. 新鲜度、单窗质量、零点稳定和独立角度分别报告，任一失败保留样本。
```

**预期输出：** 逐窗核验记录、拒绝原因、原始证据索引及各层验收状态。通过标准要求从原始数据独立复算，不能只相信采集器的通过字段。

**已验证效果：** 新鲜度实验 99 个窗口核验通过时，仍如实识别出静置相位门槛失败；HT20 真实数据保留了错误来源和时间偏移反例。

**失效条件：** 缺少独立帧、无可靠时间关联、目标帧不可区分、使用不同 PHY 但未重新验证时序。53 μs、19 μs 或 30.5 μs 等历史值不作为模板默认常数。

## Skill 04 板端迁移与黄金参考对照

**来源：** [案例 4.11](../report/llm_collaboration.md#411-doa-迁移使用黄金参考和实时计数双重证明)、4.12。适用于将 PC 上已有算法迁到嵌入式 CPU，且需要保持行为并证明实际运行位置的任务。

**输入：** 修改前实现与真实黄金样本、目标平台依赖、输出契约及比较容差、部署与回退入口、用于核验正式数据流的请求或计数指标。

```text
请先保存修改前算法和真实黄金样本，再迁移计算位置。
1. 列出现有数据流、每段执行设备和正常实时入口。
2. 提取共享算法，保持方向约定、质量门槛和拒绝语义。
3. 比较输出字段、缺失值及数值容差；ARM板端本机回放。
4. 采集新实收数据，使用原算法独立复算，不把回放当新实收。
5. 单独观察正式入口的请求与字节计数，确认旧计算路径没有自动接管。
6. 测量计算时间、CPU与传输量，注明负载、时间窗和分母。
7. 给出部署收据、失败恢复与回退范围。
```

**预期输出：** 黄金对照、板端部署凭据、新样本复算和正式入口计数。迁移成功不必要求所有数值逐位相同，但容差必须预先说明，字段与拒绝行为需符合既有契约。

**已验证效果：** DOA 迁移保留 590 窗历史等价及 24 窗新实收复算证据；正常链路观察到原始 IQ 下载增量为零。识别服务停止试验证明未静默回退到 PC 识别。

**失效条件：** 原算法本身精度未经验证、样本覆盖不足、浮点环境差异未分析、只核对源码而无执行证据。本技能证明迁移正确性，不自动证明算法物理准确性。

## Skill 05 基准数据隔离与状态恢复

**来源：** [案例 4.13](../report/llm_collaboration.md#413-基准文件不变仍可能需要拒绝当前角度)。适用于切频、采集新参考、保存和应用配置会影响实时系统的任务。

**输入：** 保存基准、实际活动配置、当前硬件状态、会话核验结果、允许沿用的具体策略和恢复入口；原位核验还需要确认参考源的物理条件。

```text
请将保存记录、表单草稿、实际生效配置和当前会话核验状态分开管理。
1. 操作前记录实际频率、参考上下文、活动记录及文件哈希。
2. 预览、载入参数和保存草稿不改变生效配置；新采集只另存。
3. 成功、失败或取消后均确认两站频率及参考上下文恢复。
4. 恢复未确认时暂停普通任务，保留操作日志和恢复入口。
5. 原位核验比较保存值，不自动重写偏置；失败保留原始相位并拒绝角度。
6. 默认授权复用与其他记录核验分别处理，不扩大授权范围。
7. UI明确待操作记录、实际生效记录、下发结果及最近核验结果。
```

**预期输出：** 状态分离、恢复日志、文件一致性、核验结果及故障分支验证。通过标准是失败路径也能恢复或明确暂停，旧参考数据不被新操作悄悄覆盖。

**已验证效果：** 保存内容不变时仍识别出物理相位不匹配；板端实际拒绝失配角度，恢复上下文和默认下发具有独立回执。

**失效条件：** 参考源不在已知原位、缺少硬件读回、跨频率或几何变化、只验证界面文字。软件恢复成功不能替代现场相位与精度核验。

## Skill 06 服务与界面真实状态验收

**来源：** [案例 4.14](../report/llm_collaboration.md#414-自启动验收发现检查脚本自身误判)、4.15。适用于常驻采集服务、受管进程和可暂停监控界面。

**输入：** 服务依赖与启用配置、实际进程归属、任务及结果计数、单调时间或结果年龄，以及界面动作预期和对应接口。仅有截图时不能完成后台业务验收。

```text
请区分配置存在、进程运行、数据增长和用户可见状态。
1. 核对服务依赖、启用关系、进程归属及真实启动参数。
2. 用boot ID与启动日志区分整机重启和应用重启，不依赖固定PID。
3. 结合目标任务、窗口计数、拒绝原因和结果年龄判断业务是否运行。
4. 对异常字段核对数据类型和语义，不以空对象等结构误判失败。
5. 对暂停与恢复定义完整快照语义，验证单请求、取消、超时与迟到响应。
6. 区分软件测试、DOM验证、浏览器视觉和实机实验；未做的环节写明。
```

**预期输出：** 配置与进程对应、业务计数、界面动作契约和已验证层级。允许正常 `waiting_target`，但需解释等待原因及目标租约状态。

**已验证效果：** 识别验收脚本空错误对象误判，正常软件重启后业务自动恢复；暂停状态不新增列表请求，恢复不积压旧请求。

**失效条件：** 只看 systemd 为 active、CPU 低或页面有数值，未核对业务新鲜度；模拟时间测试不能替代长期实测。
