# 可复用工程协作技能包

本目录把项目中经实际工程验证的协作经验提炼为提示词工程流、工作流、案例模板、校验工具和踩坑指南。目标是让陌生团队能够替换自己的工程输入后使用。项目历史、模型回答与纠错过程单独保存在 [report/llm_collaboration.md](../report/llm_collaboration.md)。

## 快速使用

1. 选定唯一提示词目录，按 `YYYYMMDD_HHMMSS_short-topic.md` 命名，一项任务同文件保存提示词与执行报告。现有工作区继续使用 `提示词/`；新工程包可使用 `prompts/`。
2. 从案例模板复制任务骨架，填写总纲领与前置记录、当前接口、操作者和模型技术任务、验证标准及恢复要求。
3. 在提示词工程流中选择技能，按工作流执行。操作者主导复杂技术取舍、精密测量及最终验收；模型承担分析、实现辅助、工具验证与证据整理。
4. 使用适用的校验脚本，记录真实输入、比较容差、失败和未执行项。任务结束后更新接口、接续状态、索引及涉及长期决策的总纲领。

## 输入输出与失效条件

输入是自己的工程、已知硬件条件、实际接口和可追溯证据；输出是可审查的修改、验证结果、纠错与可继续执行的下一步。各分类文档进一步给出具体输入、使用方法、效果来源与失效条件。

缺少原始证据、接口版本不明、物理状态未确认或参考不适用时，只能得到有限结论。模板填完、脚本通过、算法等价、短时输出稳定，均不能单独证明绝对精度或全制式支持。

## 已验证效果与复用边界

历史效果见报告中的 15 个案例，例如限定时序违例修复、IQ 新鲜度与相位质量分层、板端算法等价和基准状态隔离。校验工具是本次新增交付，其自测和实际运行范围在脚本说明中单独记录，不将其冒充历史 590 窗验证的原工具。

方法可跨项目使用；器件、频点、地址、PHY 时序、相位偏置和几何均须重新核对。尚未完成陌生团队跨项目效率测量，不宣称自动获得通用 PYNQ 能力。
