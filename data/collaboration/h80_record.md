# 底图加载失败排查与提示修复

针对“底图暂不可用，可切换卫星或离线网格”的提示，已完成图源网络抽样、图片检查和本地事件复现，并修复提示状态问题。

## 已确认原因

| 项目 | 实测结果 |
| --- | --- |
| OpenStreetMap主图源 | 不含现场位置的4级大范围抽样瓦片HTTP 200，image/png，CORS为`*`；已实际查看图片，内容是正常地图 |
| Esri备用地形图 | 同倍率抽样HTTP 403，服务器`AkamaiGHost`，响应内容为`Access Denied` |
| Esri卫星图 | 同倍率抽样HTTP 403，同样为CDN访问拒绝 |
| 当前Python网络代理 | HTTPS/ALL代理为本机`127.0.0.1:7890`；WinHTTP报告直连，二者不是同一套代理配置 |
| 对Esri的一次性直连比较 | 地形图与卫星图均约10秒超时；未更改系统/浏览器代理 |
| 提示逻辑 | 已复现旧图层迟到错误污染备用图状态、错误累计不随成功重置，以及成功后提示不消失 |

说明：图源403是实际访问失败，提示误报也是实际代码缺陷，二者可以叠加。现有证据说明当前出站链路收到Esri CDN拒绝，不能进一步断言是出口IP、地区、限流或其他具体CDN策略。单张OpenStreetMap抽样成功，也不能证明浏览器当前视野内所有瓦片均成功。

浏览器访问主机与native pipe不可用，本次无法取得浏览器Network/Console。因此尚未定位用户浏览器中主图源最初三次错误的具体请求；没有将本机Python请求当作完整浏览器网络验收。

## 本地复现

旧逻辑只用“用户选图轮次”判断事件有效性。自动切换备用图不会改变该轮次，移除后的主图层仍可能返回未完成请求的错误事件，继续累计到备用图的错误计数。

复现顺序：主图层3次错误→自动切备用→已移除主图层再返回3次错误→出现“底图暂不可用”，即便备用图没有产生这3次错误。备用图随后成功，旧代码也没有tileload成功处理，因此错误提示继续悬挂。

另一个问题是全程累计3次错误即可触发切换，中间加载成功不会清零；这会把分散的小范围失败误判成当前图源持续失效。

## 修改

- `map-controls.js`：同时检查事件轮次和图层是否仍在活动列表，忽略已移除图层的迟到事件。
- 活动图层成功加载瓦片时，重置连续失败计数并清除底图提示；后续连续失败仍会正常报警。
- 将提示改为“当前底图连续加载失败，可切换其他底图或离线网格”，不再在卫星图也可能403时固定建议“切卫星”。
- `workspace.js`更新地图模块版本参数，方便刷新加载修复。
- 未修改图源URL、代理设置、站点位置、RID/AOA数据处理或板端射频。

## 使用与剩余边界

在`http://127.0.0.1:18770/#/monitor`按Ctrl+F5刷新，优先选择“暗色底图”使用现有OpenStreetMap主图源。无网络时选择“离线网格”；RID和AOA有效位置、站点及轨迹仍可独立绘制。

代码修复解决误报与提示残留，不会使被CDN拒绝的Esri图源自动恢复。现场高倍率瓦片请求因可能向第三方披露精确位置，被自动审批拒绝，未执行；随后所有网络诊断仅使用不含现场位置的大范围低倍率样本。无需更改现场位置即可完成上述代码复现与修复。
