# DOA算法迁移至双站Linux CPU验收

2026-11-03完成。用户要求先核对原架构，再把PC单站DOA迁入A/B两台软件无线电平台，减少原始IQ传输。本轮已在两块实际板卡部署，在正式PC端口18770切换，并完成真实数据、常驻服务重启和传输计数验收。

## 修改前核对的架构

核对了`总纲领.md`、永久服务配置、PC实时调度/参考/双站桥接代码以及两站实际进程、部署源码哈希和Python环境。两板为既有Zynq Linux，Python 3.9.2，均已有NumPy 1.26.2；不需要额外安装数值库。

原数据路径：

```text
各站FPGA/双RX采样
  → side_ch / target_capture_service：原始IQ + MAC/FCS/TSF候选关联
  → PC下载每窗32776字节IQ和窗口参考报文
  → PC：LTF搜索、完整关联校验、相位、参考修正、单站角度
  → PC：同帧双站交汇、网页显示
```

原链路本来就是有限窗口采样，并非持续向PC传20 MSPS原始流。此次消除了正常实时DOA对这些原始窗口的下载和PC单站计算。

## 当前部署后的架构

```text
A/B各自FPGA/双RX采样
  → 各自Linux CPU：LTF、完整MAC/FCS/LTF/TSF校验
  → 各自Linux CPU：52子载波相位、参考有效性/偏置修正、单站角度
  → 小型结果报文：角度或拒绝原因、原始相位、质量、源MAC、帧哈希、TSF、会话/配置哈希
  → PC：结果与配置校验、目标调度、同帧双站交汇、网页显示
```

| 环节 | 当前执行位置/状态 |
|---|---|
| RF/FIR、40 MSPS、manual 0/0 dB、FPGA与双RX驱动 | 既有板端配置保持 |
| 完整检测解码及DSSS | 原分工保持，默认B站 |
| LTF搜索、削顶、完整MAC/FCS/LTF/TSF校验 | 各站Linux CPU |
| 单站相位、有效参考修正、角度反演 | 各站Linux CPU |
| 目标识别/调度、RID直显或AOA分流、布站/参考配置管理 | PC现有流程 |
| 结果契约与新鲜度检查、同帧双站交汇、地图 | PC |
| 原始IQ | 板端保留32窗环，仅按需诊断下载 |

本次迁移运行于两板Linux CPU，没有修改或重烧FPGA；没有重初始化RF，没有替换完整解码服务，没有改变接收分工或既有systemd单元。两站仍由原永久`airspace-iq.service`以`--seconds 0`启动。A/B的monitor主PID在算法服务更新及重启验证中一直保持545/525。

## 改动与兼容边界

1. 将原PC函数提取到共享`source_doa.py`、`direction_math.py`、`direction_reference.py`，保持原估计器`ofdm_ltf_unit_bins_v1`、LTF阈值、时序容差、相位方向、角度模糊解与参考规则。
2. 板端`target_capture_service.py`在本地IQ窗口上调用共享算法，增加紧凑结果环、拒绝原因及计算耗时。完整IQ、完整候选帧仍在板端有限环中，不放入正常结果响应。
3. PC随原目标租约同步`directionContext`：站点几何、原参考文件的数据副本及加载错误。上下文是有大小上限的JSON，按规范化哈希绑定，不传PC文件路径到板端读取。
4. 板端按原规则核验会话、固定增益、频率、阵距、几何与参考后应用偏置并反演角度；原参考失效时返回有效原始相位、空角度和明确原因。没有在本轮拟合或安装新现场参考。
5. PC正常`poll_iq`只消费板端结果并校验绑定，不调用PC的IQ相位算法或参考角度修正；遇到旧版板端接口会报错，不静默退回下载IQ。
6. PC对站点、目标、会话、配置哈希、TSF、帧摘要、关联标记、质量范围及参考状态继续检查。布站/参考变化后，旧观测和交汇历史失效，等待板端按新配置产生结果。

原`processing_pipeline.analyze_window`兼容入口和旧桥接路径保留给离线/历史审计；不是当前实时入口。不得通过另起旧`linux_doa`或手工采样程序与systemd服务争用side_ch。

## 验证与实测

### 数值一致性

- 从修改前源码备份加载原PC函数，对590个真实保存窗口逐窗比较原有输出字段：590/590一致，PC同平台最大数值差为0。
- 两站在自己的ARM Linux上分别回放4个实际原始窗口，每个3次。包含未标定结果和使用仅供回放的有效参考修正结果；两站全部通过逐字段一致性检查。回放参考只在安装包测试数据中使用，没有写入活动参考。
- 正式切换后，新采A/B各12个窗口并显式按需下载原始IQ，以修改前PC代码独立重算：24/24通过，最大数值差约`1.42e-14`，没有身份、FCS、LTF或TSF不一致。
- 完整地面站113项测试通过；板端/算法相关29项测试通过，包括错误MAC/FCS/TSF、削顶、非有限数值、错站/旧会话/旧配置拒绝、原参考规则、IQ常驻和增益恢复。此前一次接收分工HTTP测试遇到该环境已有的WinError 10053，单独8项与随后完整113项均通过。

单窗95%的比例只针对原IQ/窗口与结果记录，不是整个网口流量减少95%。原信源识别、RID、资源及配置流量仍存在，结果接口也会重复发送有限状态元数据。显式诊断验收阶段下载过24窗IQ；完成后停止诊断下载，再单独观察正式PC流程20秒，原始IQ计数增量为0。

当前实测信源约1窗/秒。板端CPU增加是计算迁移的预期结果；更高窗口率/高速图传需要独立吞吐验收。本轮没有宣称能在Linux CPU上逐点实时处理连续20 MSPS全流量。

### 自启动与会话

安装仅重启`airspace-iq.service`，保留原永久启用的`airspace.target`。安装后再分别执行一次受管IQ服务重启：A/B均active/running、开机启用仍为enabled；PC自动识别新会话并重新同步配置，没有人工下载IQ续算。

最终20秒观察中，两站均capturing、无IQ服务错误，两站网页观测均fresh、`processingLocation=board`，PC pipeline通信错误为空。算法核心哈希在两站一致：


最终会话为A `92fae22dca874e5ca1730290c20d6424`、B `87a9d77222b444d99b41114e62efa512`。旧参考继续被判为会话不匹配，因此当前仍显示有效原始相位、空校准角度；这不是算法漏运行。迁移没有解决或掩盖此前的绝对测向精度问题，使用校准角度前仍需重新核验参考。
