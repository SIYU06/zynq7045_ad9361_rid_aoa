## 五、功能一：开发板状态检测

页面顶部提供：

- COM 端口选择，默认 COM9。
- 波特率默认 115200。
- 连接 / 断开。
- 刷新状态。

显示三个独立状态：

**1. Linux 状态**

通过串口检查 shell 是否可执行命令、`uname -r`、`uptime`。

区分：

- 未连接。
- 串口已连接但 Linux shell 不可用。
- Linux 已启动。

**2. 驱动及 RF 状态**

检查：

- `xilinx_dma`
- `rx_intf`
- `openofdm_rx`
- `side_ch`
- AD9361 设备存在与否。
- RX LO、采样率、FIR、RX1/RX2 增益。
- 双路 IQ 参数。

显示实际读取值，并标注是否符合当前实验配置。

**3. DOA 就绪状态**

只有 Linux shell 可用、必要驱动已加载、RF 配置正确且采集接口可用时，才显示“DOA 就绪”。

Linux 启动成功不等于 DOA 就绪。

如设备刚重启、模块未加载，可提供“初始化 DOA 环境”按钮，调用已有验证过的启动流程；不能重新编译驱动或自创初始化流程。

所有串口操作串行执行，避免并发争抢 COM9。

- VALID。
- LOW_COHERENCE。
- PHASE_OUT_OF_RANGE。
- doa_estimation_failed。
- IQ 采集失败。

不要把无效角度显示成 0°。

增加三种轻量图表：

**图一：原始相位差随窗口变化曲线**

用来观察相位是否稳定、有无明显突变。

**图二：DOA 角度散点图**

## 八、功能四：软件无线电设备和 DOA 可视化

用 SVG 绘制实际设备示意：

- 一个横放的软件无线电平台盒子。
- 盒子一侧两个 SMA 接口。
- 两根约 20 cm 的 SMA 延长线。
- 两根竖直、平行的接收天线。
- 两根天线的中心间距标注 5 cm。
- 标注 RX1、RX2。

推荐将俯视阵列位置和设备外形结合绘制。

**角度坐标规定：**

- 两天线中心连线构成阵列基线。
- 基线的水平垂直方向为阵列法线 0°。
- 候选方向范围为 −90°～+90°。
- 方向射线从阵列中心向外绘制。
- 正负角度的左右映射先作为明确标注的软件显示约定；尚未通过真实测向标定，不得称为已经确认的物理左右方向。
- 双天线前后镜像歧义尚未解决，显示“存在前后方向模糊”。

可视化规则：

1. 若存在明显集中的 VALID 角度区间，可绘制该区间的候选方向扇形。
2. 若存在多个分散角度区间，仅绘制候选分布，不强行给出唯一方向。
3. 若本轮几乎没有有效角度，显示“暂无可信候选方向”。
4. 图上同时显示本次有效窗口数、角度区间及当前相位标定状态。
5. 用户点击某个有效窗口时，可高亮该窗口对应的候选角射线。

核心目的：让用户清楚看到程序本次输出的是哪个角度，以及它相对于阵列法线的方向。

不要画出未经确认的具体无人机位置，也不要自动标记设备身份。

## 九、功能五：自动分析本轮结果

不接入 AI API。

使用本地 Python 统计规则，生成一段简洁中文分析。

重点说明：

1. 本次共采集 N 窗，IQ 成功率是多少。
2. VALID 候选角占比多少。
3. 相位和角度是否集中。
4. 是否存在明显低相关、相位越界和解算失败。
5. 是否存在值得关注的候选角区间。
6. 如果未标定，明确提醒当前无法验证真实测向精度。

分析控制在 3～5 句话，不需要生成冗长实验报告。

例如：

“本次共采集 200 窗，IQ 成功率 100%，VALID 候选角占比 35%。相位分布较分散，部分窗口相关度偏低。候选角度分布在多个区间，未形成稳定主导方向。当前相位偏置未完成实测标定，输出角度仅供调试参考。”

实际数字必须来自本次采集结果。

## 十四、2026-10-31 故障修正记录

### 1. `iq_dual`、`iq_len` 总是为 0

- 原因不是驱动初始化失败，而是网页读取了不存在的只读 sysfs 参数文件；`side_ch` 中这两个 module parameter 的权限为 0，不能从 `/sys/module/side_ch/parameters/` 读取，旧代码随后把缺失值默认为 0。
