## 二、先回答两路增益和天线的问题

### 1. 可以分别设置 CH1、CH2 的硬件增益

AD9361支持按接收通道设置增益和增益模式；官方接口也明确区分 RX1/RX2 的增益控制。[ADI接收链说明](https://github.com/analogdevicesinc/no-OS/blob/main/drivers/rf-transceiver/ad9361/README.rst#receive-chain-settings)

本工程 Linux 已有两路属性 `in_voltage0_hardwaregain`、`in_voltage1_hardwaregain`，以及对应的 `gain_control_mode`。此前工具只是给这两个属性写入同一个数值。因此独立增益首先是**现有软件工具扩展**，不需要先重新做 FPGA。

但应先核验命名映射：拟定 CH1 对应 IIO voltage0、CH2 对应 voltage1；再确认它们与原始 IQ 的 I0/Q0、I1/Q1及物理 RX1/RX2的对应关系。不能只凭变量名断言映射正确。

拟新增配置如下，**当前 `channel_capture.py` 尚未实现这些独立参数，下一轮需先实现，再实测**：

| 拟议参数 | 作用 |
|---|---|
| `--rx1-gain-db` | 单独设置CH1手动硬件增益 |
| `--rx2-gain-db` | 单独设置CH2手动硬件增益 |
| 原 `--fixed-gain-db` | 保留为两路同值的兼容入口；与独立参数互斥，避免歧义 |
| 增益读回与配置指纹 | 保存两路实际模式、实际增益及对应标定版本 |

### 2. “幅度差2.8倍”不是“硬件增益参数相差2.8倍”

已读回的两路设置都为10 dB；观测到的是 ADC IQ 的 RMS 幅度差。接收幅度还受天线、馈线、接头、输入匹配、传播路径与射频通道响应影响。

对幅度比 R，用 `20 log10(R)` 换算；2.8倍约为8.94 dB，功率比则约7.84倍。本次60个窗口的逐窗 RX1/RX2 幅度比中位数为2.823，最小约2.128、最大约4.758。**三批中位数接近，不代表每个包都固定差2.8倍。**

下一轮可以按约9 dB作为初始对照量，不应把它当成永久校正常数。

### 3. 优先减小较强路，逐级验证；不要直接猛加较弱路

以当前接法、当前源强度为准，CH1较强：

| 顺序 | CH1 / CH2设置 | 目的 |
|---|---|---|
| 对照 | 10 / 10 dB | 保留同条件原始基线 |
| 第一步 | 7 / 10 dB | 小幅降低强路，观察幅度与相位是否改善 |
| 第二步 | 4 / 10 dB | 仅在前一步质量允许时继续 |
| 第三步 | 1 / 10 dB | 测试约9 dB差分设置，不强求幅度恰好1:1 |
| 返回对照 | 10 / 10 dB | 检查回程可重复性，区分增益影响和时间漂移 |

这只是待测的候选组合。若设置减小强路导致相干或接收质量下降，应回退，而不是为了幅度相等继续减小。若较弱路确实受量化或噪声限制，可在核对峰值余量后另测 CH1=10、CH2=13/16/19 dB；本轮不预先承诺这些值安全或更优。此前近距离20 dB曾削顶，不能只看平均 RMS 判断余量。

改变模拟增益可能改变工作点、瞬态或复数通道响应；每个增益组合都要独立检查相位，不能改完增益继续套用原偏置。目标是两路都不饱和、有效信号足够、相位可重复，而不是强制电平相等。

### 4. 正实数数字归一化能调幅，不能修复相位跳动

当前主算法的核心是：

`C12 = Σ conj(x1[n]) · x2[n]`，`相位差 = arg(C12)`。

把一路乘以正实数 a，只会把 C12乘以a，不改变其角度；归一化相干度中的比例也会相消。它同时放大该路信号与噪声，不能恢复丢失的接收信噪比。因此“把CH2数字乘2.8后两路看起来一样大”不等于解决DOA。

真正的相位补偿需测量复数通道响应，包括固定相位与必要的频率响应；不得在每个未知方向的数据上自行估计一个偏置强行归零。

### 5. 天线问题如何排序

目前不以“天线坏了”为默认结论。用户的判断可作为优先假设：先检查固定通道响应、增益组合和算法取样段。

但也不能认定天线/馈线已排除：已完成的互换同时改变了接触质量，且中间断电重启；换线前还有原RX1接触不良这一关键事实。当前还没有“两种接法都接触可靠、环境固定、往返复现”的完整对照。

先完成独立增益与离线算法检查。若仍不稳定，再做第六节的低成本定位试验，不先要求更换天线。

## 三、推荐算法与备选路线

推荐主线：**双通道相位干涉测角 + 双路复数响应标定 + 分突发质量门控 + OFDM固定前导参考 + 跨包稳健统计**。

| 方法 | 本硬件的定位 | 决策 |
|---|---|---|
| 校准后的双天线相位差 | 两路同步、5.9 cm基线直接可用，计算量小 | 主测角方法 |
| OFDM LTF相位/子载波融合 | 已有OpenWiFi链路；固定训练段有利于统一测量口径 | 优先新增的OFDM分支 |
| 通用突发互谱/子带相位 | 不要求RID或MAC，适合未知窄带或可分子带信号 | 全信道主线的通用分支 |
| 两阵元MUSIC/ESPRIT | 可作为单主源结果交叉检查，不能补出缺少的空间维度 | 对照，不作为主要救场算法 |
| 普通GCC/TDOA峰值 | 5.9 cm最大几何时延约0.197 ns，20 MSPS样点间隔50 ns | 不作为当前主线 |
| 时间平滑/卡尔曼跟踪 | 能平滑已可靠且已正确关联的观测 | 放在标定和验收之后 |

经典MUSIC要求信号子空间维数小于阵元数，相关多径也会使性能退化。两阵元无法依靠换算法就稳定分解任意多个同频重叠源。[MUSIC模型与限制](https://www.mathworks.com/help/phased/ug/music-super-resolution-doa-estimation.html)

在当前频率下，波长约12.30 cm，5.9 cm接近但小于半波长。采用正前方为0°时：

`φ = 2π f d / c · sin(θ) + φ硬件`，其中当前系数约3.0135 rad。

相位5°在零度附近约对应1.66°角变化；相位波动和角误差不能混写。两根线阵天线仍有前后镜像、仰角与端射方向精度下降等限制。先验收正前方的指定扇区，再讨论更宽视场；不能直接承诺360°。

## 四、下一轮具体怎么做：先软件和增益，再移动信源

### 步骤1：只复算连接可靠的60窗，不急着再摆左右位置

输入上述 `outdoor_secure_gain10_20261101_1514` 原始IQ、PCAP和元数据，保留失败记录。优先检查：

- 两路峰值、正负削顶、RMS、DC、频谱、突发分段、包间相位和时间趋势；ADC正满量程判据保留32752，负满量程为−32768。
- 双通道样点交织和通道顺序；共同信号的相对时延、频率响应是否稳定，是否出现不合理的整样点错位。不要仅因相位异常就自动移位对齐数据。
- 对比整窗、当前相干分段、固定OFDM前导三种测量口径。使用相同数据、相同训练/留出划分，不事后选择“最稳定的一小段”宣布成功。
- 把数据按时间或批次划分，训练只用最早一部分，后续批次作为独立检验。不能随机打散相邻包后夸大泛化能力。

已有 `tmp/probe_reference_ltf.py` 只是历史探索脚本，搜索范围和数据路径固定，并非验收通过的LTF检测器。应先确认当前4096点窗口是否完整包含LTF，再用训练序列相关及双长符号结构定位；找不到时拒绝该分支，不猜固定样本索引。

### 步骤2：实现独立增益并做最小闭环对照

扩展 `fixed_gain_profile`、`channel_capture.py`、参考采集工具的两路参数，使旧的同值接口保持兼容。必须做到：保存原模式与增益、逐路写入并读回、检查参数冲突、等待稳定、清旧FIFO、保存活动配置、结束或可处理异常后恢复。记录硬件参数实际读回值，而不是只存用户输入值。

正式扫描前先做一次小幅通道映射检查：10/10 → 7/10 → 10/10 → 10/7 → 10/10，查看分别改变哪个IIO属性会使哪路原始IQ幅度响应。若环境波动使结果不清楚，保留未确认状态，再用同源输入等条件确认；不要在映射不明时把强弱补偿写反。

先在用户确认接头可靠、源固定、人员离开线缆后，按第二节候选组合逐级测试。每个组合至少3批、每批目标30个来源核验窗口；按当前约1 Hz广播留足超时，并保存未达数量的结果。增益切换后建议先留1 s稳定时间并丢弃最早数包，这是待验证的工程等待量，不宣称来自芯片固定要求。

一旦出现削顶、明显接收恶化或异常状态，结束该设置并恢复；不为“凑满数量”放宽来源和质量门槛。若某设置已满足要求，不继续穷举更多无必要组合。

这两路与OpenWiFi monitor共享同一射频前端。临时改MGC可能改变RID接收情况，应同时记录monitor帧、坏FCS、参考帧等条件统计；不能声称调DOA增益对RID完全没有影响。

### 步骤3：新增LTF/子载波测相分支，与现算法公平比较

OpenOFDM文档明确：20 MSPS的长前导包含重复的64点训练符号，可用于符号对齐；训练序列也用于子载波信道估计。[长前导对齐](https://openofdm.readthedocs.io/en/latest/sync_long.html)、[子载波均衡](https://openofdm.readthedocs.io/en/latest/eq.html)

实现顺序：共同定时定位 → 检查重复长符号质量 → 两路使用同一采样区间 → 估计每路LTF响应 → 比较有效子载波的相位差 → 剔除深衰落/低质量频点 → 圆周稳健融合。DC与未使用子载波不参与，不能将噪声频点等权平均。

若有可靠的电气/已知方向参考，保存每频点复数比值 `G校准[k]`；观测量可写为：

`q[k] = H2[k] · conj(H1[k]) / G校准[k]`。

该G必须只包含明确参考条件下测得的响应。用露台零度源取得的G可能同时包含当时的传播环境，应标为“该布置参考”，不能未经验证当作纯硬件传递函数。

禁止把未知目标每包的相位斜率全部拟合并消除，那可能同时消掉真实几何信息。算法评估同时报告来源核验数、拒绝数、相位离散度、处理延迟及配置依赖；相干度高只是条件之一。

### 步骤4：冻结选定增益和算法，验证零点重复性

先保留现有标定门槛，不因失败而放宽：当前代码至少10个参考记录、至少90%内点、训练相位离散不超过5°。另外建议将后续工程目标设为：三批各至少30个来源核验窗口，每批圆周标准差力争≤3°，批均值相对训练参考偏移力争≤3°。这是本方案提出的待验收目标，尚未实现。

冻结条件包括增益对、频率、采样率、端口、馈线/天线编号、通道顺序、算法版本和标定版本。更改其中影响响应的条件后，至少重新核验，不跨组合套用偏置。

若零点仍不稳定，进入第六节的定因分支，不继续要求用户反复移动到±角度。只有零点可重复，左右角度试验才有解释价值。

## 五、零点通过后，如何做真实单站测角验收

### 1. 用尺量几何，不用地图或两个GPS点计算一米基准角

在地面标出天线中点O、正前方垂线、前向距离D与横向偏移x；源和天线高度接近，固定支撑、不手持。角度真值为 `atan2(x,D)`。记录站在开发板一侧、朝参考源看时哪边为正，以及对应RX顺序，先检验左右符号。

若仍使用前向D=1 m：

| 目标方向 | 横向偏移x |
|---|---:|
| 0° | 0 |
| ±10° | ±17.63 cm |
| ±20° | ±36.40 cm |
| ±30° | ±57.74 cm |
| ±45°，空间允许后再测 | ±100 cm |

若D改为2 m，所有x加倍；“横移20 cm就是11.3°”只对D=1 m成立。1 m距离下横向误差1 cm已约0.57°，摆放公差必须记录。距离是否足够形成合适远场还取决于天线尺寸，不能仅凭“一米”给整个安装结构作保证。

### 2. 建议顺序与数量

先测 `0 → +10 → 0 → −10 → 0`，每位置至少30个来源核验窗口，用同一个冻结偏置；同一角度的所有包不得再次独立归零。通过后再扩到±20°、±30°，最后考虑±45°。

优先让整轮保持同一RF增益会话，仅因物理调整清采集FIFO；等待用户摆好并离开后采样。若中间重启、改增益或重新调谐，记录会话边界，重新核验零点，再继续。

建议首版有效扇区为正前方±30°；扩展到±45°需单独报告。建议目标为各测试角平均绝对误差≤3°、95分位绝对误差≤5°，并报告最大误差与拒绝率。它们是预设工程目标，不能在结果出来后临时换成更宽阈值。

验收分母分别记录“可核验参考帧”“采到的IQ窗”“来源匹配窗”“质量合格窗”“最终角度观测”，避免只挑接受窗口汇报精度。当前有采样空隙，条件统计不能直接写成全天候检出率。

### 3. 再验证距离、重启与场景适应性

同一角度增加至少一个可行距离，例如由1 m到2～3 m，保持源、天线高度和电脑位置有记录，避免把源重新放到电脑旁形成新的强反射布置。先测未重标定的表现，再决定需要何种参考更新；不能每个场景重新归零后宣称跨场景通用。

额外做一次重启前后同位置检查，回答“标定能否跨启动保存”。未通过前，部署应要求每次启动重新参考核验，而不是悄悄读取旧偏置。

## 六、什么时候再查天线，怎样用最少实验区分原因

### 分支A：可靠连接后的A/B/A互换，低成本备选

给两根天线、两条馈线分别编号，拍照或画接线图。只交换板端外部馈线，天线实体与空间位置不变，两种接法都确认牢固，做原接法A → 互换B → 恢复A。分别采未削顶参考，不用跨接法绝对相位直接算角度。

- 弱幅度若跟外部组合往返切换，优先检查该天线/馈线组合或其空间路径；仍不能直接判定天线本体损坏。
- 弱幅度若固定留在同一个数字接收通道，优先检查板端接口、通道响应、增益映射与IQ映射。
- 若重插后消失，优先复查接触，不把第一次接触不良的数据当成可靠对照。

若用户选择断电换线，每次都记录重启因素；不能把它当作严格连续RF会话。不要为了避免重启而强迫用户在不便操作的状态下带电插拔。

确有必要时，再分别交换馈线、交换天线本体；每次只改变一种因素。未出现证据前不建议直接购买或更换天线。

### 分支B：同源二分电气对照，诊断区分度更高

若能借到适合频段的50Ω二路功分器、匹配馈线和必要衰减器，用同一受控低电平信号分别送入两接收口，测量双路复数响应及重复性。这能大幅减少空中天线和多径的不确定性，优先于继续堆算法。

先确认器材和输入电平，再操作；不要把发射机输出不经核对直接接到接收口。交换功分器两输出支路再测，可检查功分器/馈线本身的幅相差。单次二分输入结果也要保留支路不理想的限制。

同源输入仍不稳定时，优先查数字采样对应、驱动/PL配置、RF跟踪和通道响应；同源稳定而空中不稳定时，再聚焦天线安装和传播环境。此处是诊断优先级，不是单次试验即可证明唯一根因。

## 七、单站算法通过后，怎样完成工程主线

| 阶段 | 实现内容 | 完成证据 |
|---|---|---|
| 单站测角核心 | 独立增益、标定配置管理、LTF和通用分突发测相、质量拒绝 | 零点、独立左右角度、距离及启动复核 |
| 全信道观测 | 自由采样与能量/OFDM辅助触发组合，保存未知信号；按突发/时频分组 | 多类信号录制、采样空隙、条件接受率、误报与漏观测说明 |
| 目标辅助识别 | RID身份、Wi-Fi/BLE/其他特征分层记录，区分已确认、疑似、未知 | 不把未解码信号、普通AP或多个多径峰直接说成无人机 |
| 地面站实测接入 | 上报相对角、角度定义、配置和标定版本、质量、时间、来源、拒绝原因 | 不从RID航向构造DOA，不显示未经验证的正式角度 |
| 单站现场交付 | 固定结构、启动自检、标定有效性检查、长时间稳定性和可复现日志 | 明确有效频率、扇区、距离/信号范围与失效条件 |
| 双站定位 | 两站位置/朝向、观测时间与目标关联、交汇及几何质量判断 | 两站单独合格后，用已知位置目标做独立二维定位验收 |

主线必须继续覆盖当前通道内的所有可观测信号，不能把ESP32的MAC触发保留成正式白名单。未知协议可先输出“未知突发+质量+相对方向”，身份未确认不能写成已识别无人机。两路天线无法承诺分离任意同时同频的多个源。

OFDM LTF分支并不等于支持BLE、DSSS或所有FPV协议。对非OFDM信号，先以通用子带/突发相位法做独立校准和有控制的信号验证，结果不合格则拒绝输出角度。当前通带监测也不等于同时覆盖整个2.4 GHz频段；扫频有驻留和漏观测问题，须另记。

正式观测宜先使用已验证的固定增益对。若以后需要AGC提高动态范围，就必须解决每窗实际增益/瞬态的记录与增益相关标定；不能把手动增益标定直接用于任意AGC状态。

5.9 cm间距的半波长频率上界约2.54 GHz，不可把当前相位反演无条件搬到5.8 GHz。需要更高频支持时，另行设计间距、有效扇区或消歧方案。

单站阶段先输出可靠相对方位，不从两个通道直接估计可靠距离。双站阶段需独立获得基线与站点朝向；可用实测相对坐标先验收，不必把浏览器90 m位置当作站点真值。两站FPGA TSF并不天然共用一个起点，要处理观测时间窗口与目标关联；接近平行的两条方位线应拒绝或给出大的定位不确定度。

## 八、下一轮可以直接复制使用的提示词

你正在继续“空域知微”项目的室外单站DOA开发。先读本文件和11.01_15.09换线报告，优先使用两路接牢后的 `outdoor_secure_gain10_20261101_1514` 数据；保留接触不良、削顶、左右测角失败的历史记录。OpenWiFi真实RID接收和Web地面站已经运行，不重做SD/内核/FPGA部署。本轮计划不等于已有功能，逐项核验实现状态。

已知硬件是双接收AD9361、XC7Z045、5.9 cm竖直平行双天线，当前信道6。用户确认原RX1外部接触不良，之后两路已接牢。最新两路同为10 dB，CH1/CH2幅度中位约2.82，但逐窗约2.13～4.76；零点相位重复性仍未通过。可以独立设增益，不把幅度差当成已确定的芯片增益误差，不预设天线故障。

先离线复算有效连接数据并核验IQ/通道映射、削顶、包内测相区间。随后扩展逐路增益参数和恢复机制，保留原同值入口，读回并保存实际配置。优先做10/10对照，再按需逐级降低强路到7/10、4/10、1/10，最后返回10/10；不要一开始盲目给弱路加9 dB。每组合分别检查电平、相位、接收情况及跨批次重复性，禁止改增益后套旧偏置或只调数字幅度宣布解决。

以“校准相位干涉+分突发门控”为主线，新增有明确同步与留出验证的OFDM LTF/子载波分支；MUSIC仅作对照，普通GCC峰值不作主线。固定训练/留出划分，不用未知目标自拟合相位把方向抹掉，不用平滑掩盖系统偏差。若零点仍不稳，按本文分支做可靠连接A/B/A或借用同源二分对照，先说明实验目的，再只请求用户完成必要物理操作。

零点通过后再让用户按尺量几何摆0、±10、±20、±30°，同一配置和偏置做独立验收，定好扇区、误差和拒绝规则；之后才推进多协议/未知信号观测和双站定位。任何参考MAC筛选仅用于有界标定，正式监测仍覆盖当前通道所有信号。不能把RID航向当DOA、地图5 m比例尺当5 m定位精度、多个突发或多径峰当多架无人机。

每轮保存原始双路IQ、PCAP、完整MAC/RID/FCS/TSF关联、源几何、两路实际增益、采样配置、标定版本及未通过窗口；缺少来源或真值就如实标未知。已读回恢复与当前在线状态分开报告。报告和下一轮提示词写入“提示词”文件夹，文件名使用 `MM.dd_HH.mm简要标题.md`，日期与时间之间为下划线。
