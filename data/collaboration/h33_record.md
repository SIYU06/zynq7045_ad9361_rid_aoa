# 地面站电脑位置标记修正

## 一、问题与当前硬件限制

用户反馈自动定位误差约 88～90 m，手动选点后仍显示“地图选点”的加号标记，而没有校正电脑标记。用户要求自动定位优先，手动校正补充，并希望检查电脑内置 GPS 能力。

前轮只读检查得到电脑型号 HP Pavilion Gaming Laptop 15-dk2xxx，设备枚举未发现可用 GPS/GNSS 或定位传感器，Windows 定位服务正在运行。调用 Windows 原生 `Geolocator` 得到 `PositionSource=WiFi`、报告误差 90 m。这是可用来源检查结果，不等于已经证明物理主板绝无未启用的 GNSS 硬件。页面选择浏览器结果时可能报告约 88 m；两者都不能被描述为米级卫星定位。

## 二、最终交互与实现

1. 未保存手动电脑位置时，默认同时尝试 Windows 系统位置与浏览器位置，选择报告误差较小的有效结果；误差相同优先系统来源，过期或无效结果拒绝使用。
2. 点击“设置电脑位置”后在地图单击，直接移动唯一的电脑蓝点。输入经纬度或选择地点搜索结果也走同一路径，不再保留独立的“＋”选点标记或第二次确认按钮。
3. 自动位置显示实际来源与报告误差；手动位置显示“手动设置 · 精度未测量”，清除原自动误差圈，不把原先的 88 m 或 90 m 沿用到手动位置上，也不伪造更小误差。
4. 手动位置保存到当前浏览器、当前端口的本机存储，刷新恢复；晚到的自动定位回调不能覆盖它。再次点击“自动定位”可解除手动锁定，定位失败则保留原点。
5. 删除旧加号图例，位置区域统一显示电脑坐标和来源。页面、主脚本、位置模块和样式采用新版本号，静态资源设为 `Cache-Control: no-store`；打开新版本 URL 避免沿用旧页面。

电脑位置仍只影响电脑标记与地图视角，不修改 RID 广播目标坐标、不注入真实测向站坐标，不移动目标以制造“电脑与无人机重合”的假象。

修改入口：`rid_receiver/ground_station/map-controls.js`、`app.js`、`index.html`、`style.css`、`serve.py`；系统定位通过 `computer_location.py` 和 `windows_location.ps1` 读取，保留超时、定位失败与真实来源。README 与页面说明同步更新。

## 三、验证与运行状态

- 前端检查通过：自动来源选择、报告误差相同优先系统来源、手动与自动回调竞争、唯一电脑标记、误差圈清理、保存恢复、自动失败保留、零值坐标、越界坐标拒绝，以及地图/坐标/地点搜索三种校正入口。
- 既有 RID 与 DOA 数据独立、实时 RID 连接与断连测试通过；Windows 定位读取的来源保留、无效坐标、权限失败、超时共 4 项检查通过。
- 重启本机地面站服务使新响应头生效，未重启开发板或改动射频配置。实际 HTTP 检查确认 HTML、主脚本、位置模块、样式均为 200、新版本匹配、`Cache-Control: no-store`，位置模块不再含旧 `picked-marker` 创建路径。
- `/api/rid` 实测 `connected=true`、1 个实时目标，地面站已打开新版地址 `http://127.0.0.1:18770/?computer-position=3`。
- 前轮浏览器界面自动验证因工具不能可靠识别当前网址而终止；本轮以逻辑回归和实际服务响应验证为证据，未宣称已经目视验收用户当前屏幕。

## 四、下一步提示词

用户当前可以在新版页面点击“设置电脑位置”，再点击实际地点，看到同一个电脑蓝点移动并保存。若仍见旧加号，先检查地址与页面版本，不再以重复说明“浏览器有误差”代替修复交互。

软件流程和图例修正不提高硬件定位精度。需要可靠自动位置时，应接入位于电脑/接收站附近的独立 GNSS 数据，并保留来源、定位有效性、时间与不确定度；不能把无人机/RID 模块的位置自动当作电脑位置。固定站可使用独立核验的测量坐标，但须明确坐标系与实际天线参考点。
